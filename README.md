# Sprint_7
### Тестирование сервиса API ЯндексСамокат
    Автоматизированные тесты для проверки функциональности API сервиса Яндекс Самокат. Проект обеспечивает проверку ключевых бизнес‑процессов: работы с курьерами и заказами.

Стек технологий:

Язык программирования: Python 3.14;     
Фреймворк для тестирования: PyTest;     
Генерация тестовых данных: Faker;       
HTTP‑клиент: Requests;  
Отчётность и визуализация результатов: Allure;  
Тип тестирования: REST API(прямой вызов).   

    Реализованные сценарии
1. Работа с курьерами
 - Успешная регистрация курьера с заполнением обязательных полей (login, password, first_name).
 - Запрет на дублирование курьеров — проверка уникальности логина (ожидаемый статус 409 Conflict и сообщение об ошибке).
 - Обработка ошибок при отсутствии обязательных полей (статус 400 Bad Request и сообщение о недостающих данных).
 - Авторизация существующего курьера с получением id в ответе (статус 200 OK).
 - Обработка неверных данных при входе:
   - неверный или несуществующий пароль;
   - отсутствие логина в запросе;
   - попытка авторизации несуществующего пользователя.
 - Удаление курьера после завершения тестов (очистка данных, статус 200 OK).

2. Работа с заказами
 - Создание заказа с разными комбинациями цветов:
   - только BLACK;
   - только GREY;
   - оба цвета (BLACK и GREY);
   - без указания цвета (пустой массив).

3. Проверка, что успешный ответ на создание заказа содержит поле track (статус 201 Created).

4. Получение списка всех заказов — проверка, что ответ содержит массив заказов (orders) и имеет статус 200 OK.

        Команды для запуска:    

 - Запуск тестов в один поток (подробный вывод): `pytest -v`

 - Запуск тестов с сохранением результатов для Allure: `pytest tests/ --alluredir=allure_results`

 - Формирование отчёта Allure: `allure serve allure_results`
